# Security and credential boundary

Firebase Hosting/Auth belongs to **slamsort-245f9**. Cloud Run/Vertex billing belongs to **slamsort**. Firebase Admin explicitly verifies against `FIREBASE_AUTH_PROJECT_ID`, never the Vertex/ADC project. The signature, expiration, audience and issuer must be valid before inference. No user-management RPC or revocation lookup is performed; current valid Firebase ID tokens remain valid until expiry.

AI defaults disabled. Public mode requires `SLAMSORT_PUBLIC_AI=true`, valid public Firebase web configuration, exact allowed HTTPS origins and Vertex configuration. Local and public flags are mutually exclusive. Public mode binds `0.0.0.0`, uses Firebase Bearer authentication, and never issues or accepts the local ephemeral token. Local mode binds `127.0.0.1`, requires strict loopback Host/peer and same-origin Fetch Metadata for exactly localhost:5173 or 127.0.0.1:5173, and is disabled in compiled/production runtimes. Public inference is disabled if the Firebase Auth emulator is configured.

CORS allows only exact `ALLOWED_ORIGINS`; no wildcard, arbitrary reflection or credential cookies. Approved preflights expose only known routes/methods and Authorization/Content-Type. CORS is not authentication: every paid public request must independently pass Admin SDK verification. The browser initializes modular Firebase/anonymous sign-in only on an approved AI action; config bootstrap does not create an account. Client auth is memory-only. Firebase web API keys/app IDs are public metadata, while Google refresh/access tokens, ADC and service-account keys are credentials.

Never open, copy, print, commit, upload or bake ADC, private keys or environment files into images. The attached runtime identity supplies Vertex credentials; verification uses Firebase signing certificates and the explicit auth project. No downloaded service-account key is needed. Vite retains isolated `apps/web/env-public`; there is no dotenv loader. `VITE_API_BASE_URL` is the only public build-time setting, and it must be an HTTPS origin. Public Firebase metadata comes from runtime `/api/config`, not committed source.

Both modes validate bounded request/output schemas: 24 KiB body, prompt 2000 chars, excerpt 8000 chars, 1–5 safe unique folder segments. Unknown fields/path traversal/unknown bucket IDs are rejected. Provider errors, excerpts, Bearer tokens and environment values are never logged. Limits per instance: 12 admitted model requests/minute and 2 active; per UID: 6/minute and 1 active; verification: at most 8 active with 8-second deadline. UID maps prune idle entries and cap at 1000. Model deadline is 25 seconds with abort signal, SDK timeout 24 seconds, one attempt. These are per-instance memory limits, not durable global quotas; Anonymous accounts can be recreated. Operators must review instance caps, quotas and billing alerts.

The root Dockerfile copies explicit manifests/API/shared source only. Allowlisted `.dockerignore` and `.gcloudignore` additionally exclude private credential/environment files, Git, node_modules, logs, private stores, work/tests/artifacts. Runtime runs as non-root with production API dependencies/artifacts only. Static Hosting contains only `apps/web/dist`; no cross-project Run rewrite exists. `prepare:hosting` pins CSP to the actual API HTTPS origin while preserving blob previews/PDF workers and bundled Firebase Auth/Phaser support.

Planning sends approved organization prompts only; opt-in child drafts add approved category labels, never membership names. Hints show exact outgoing metadata/name/excerpt for explicit approval. Model output is advice; the journaled local file engine is the only filesystem mutation boundary. Copy/verify/remove remains non-atomic; external applications can race final checks. Retain journals until recovery is resolved, keep uncertain copies, and never recursively delete source folders.

Before publishing: inspect tracked paths/diffs, run a reputable secret scanner against staged source/history without printing suspected live values, check ignore rules, and confirm no private fixtures, credentials, stores, environment files or logs are tracked. Rotate exposed credentials through their issuer. Deployment, IAM and GitHub publication are supervisor-owned. No CI deployment keys or GitHub Actions are included. See [deployment handoff](docs/deployment.md) for exact public configuration and human-run commands.
